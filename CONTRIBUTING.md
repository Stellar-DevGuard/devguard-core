# Contributing

Thank you for helping improve Stellar DevGuard.

1. Check existing issues; discuss significant changes before implementing them.
2. Fork the repository, create a descriptive branch, and make one focused change per pull request.
3. Run `npm ci`, `npm run check`, and `npm test` locally.
4. Add tests for new behavior and update docs when public commands or APIs change.
5. Explain what changed, how it was tested, and any RPC network assumptions in the PR.

Do not include private keys, seed phrases, account credentials, or proprietary endpoint tokens in issues, test fixtures, logs, or PRs. Report vulnerabilities privately to the maintainers via GitHub's private vulnerability reporting when enabled, otherwise contact the repository owners before disclosure.

We welcome genuine contributions. Contributions are reviewed for correctness, clarity, security, and maintainability, regardless of reward program participation.
